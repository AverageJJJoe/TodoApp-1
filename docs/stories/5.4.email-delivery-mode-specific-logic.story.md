## Status
Draft

## Story
**As a** user  
**I want to** receive emails formatted for my workflow mode  
**So that** emails match my preferences

## Acceptance Criteria
1. In cron job, check `users.workflow_mode`
2. If `fresh_start`: Query all tasks → Send email → `UPDATE tasks SET archived_at = NOW()` (clear app)
3. If `carry_over`: Query incomplete tasks only → Send email → Add "(from yesterday)" indicator for old tasks
4. Test both modes: Receive correct email format
5. Fresh Start mode: App is empty after email sent

### Database Schema Context
[Source: `docs/architecture/database-schema-data-model.md`, lines 58-85]

**Tasks Table - Archive Fields:**
- `status VARCHAR(20) NOT NULL DEFAULT 'open' CHECK (status IN ('open', 'completed', 'archived'))`
  - Status enum: `'open'` (default), `'completed'`, `'archived'`
  - Fresh Start mode: Tasks set to `'archived'` after email sent
- `archived_at TIMESTAMP DEFAULT NULL`
  - Timestamp when task was archived
  - Set to `NOW()` when task is archived for Fresh Start mode
  - Used to mark tasks as cleared from app (Fresh Start mode)

**Archive Update Pattern:**
```typescript
// Update all open tasks to archived after email sent
await supabase
  .from('tasks')
  .update({
    archived_at: new Date().toISOString(),
    status: 'archived',
    updated_at: new Date().toISOString()
  })
  .eq('user_id', user.id)
  .eq('status', 'open');  // Only archive open tasks (don't touch completed tasks)
```

**Query Pattern for MainScreen (Fresh Start Mode):**
```typescript
// MainScreen loads only open tasks (excludes archived)
const { data } = await supabase
  .from('tasks')
  .select('*')
  .eq('user_id', user.id)
  .eq('status', 'open')  // This excludes archived tasks
  .is('deleted_at', null)
  .order('created_at', { ascending: false });
```

**CRITICAL:** After email sent with `archived_at` set, tasks have `status = 'archived'`, so MainScreen query (which filters `status = 'open'`) will exclude them → App appears empty ✓

**Task List HTML Generation:**
```typescript
const taskListHTML = userTasks
  .map((task) => {
    const taskText = escapeHTML(task.text);
    
    // Carry Over mode: Add "(from yesterday)" indicator for old tasks
    let indicator = '';
    if (user.workflow_mode === 'carry_over' && user.last_email_sent_at) {
      const isOldTask = new Date(task.created_at) < new Date(user.last_email_sent_at);
      if (isOldTask) {

  })
  .join('');
```

### Technical Constraints

**Workflow Mode Logic:**
- Fresh Start: Archive ALL open tasks after email sent (clear app)
- Carry Over: Keep tasks open, show "(from yesterday)" indicator for old tasks
- Archive update must happen AFTER email sent successfully (not before)

**Task Querying:**
- Fresh Start mode: Query ALL open tasks (not just new ones) for email
- Carry Over mode: Query all open tasks (unchanged from current implementation)
- Archive update: Only update tasks with `status = 'open'` (don't touch completed tasks)

**Email Formatting:**
- "(from yesterday)" indicator only shown in Carry Over mode
- Indicator only shown for tasks older than `last_email_sent_at`
- Indicator styling: Subtle gray (#999), smaller font (12px)
- First email (no `last_email_sent_at`) won't show indicator

**Archive Timing:**
- Archive update must happen AFTER email is sent successfully
- If archive update fails, log error but don't fail email send
- Archive update should not block email sending to other users

**MainScreen Query:**
- MainScreen already queries `status = 'open'` (correct)
- Archived tasks (`status = 'archived'`) are automatically excluded ✓
- No changes needed to MainScreen for this story
