# Story 7.7: Pre-Launch - Dark Mode Support

## Status
Approved

## Story
**As a** user  
**I want to** switch between light and dark themes  
**So that** I can use the app comfortably in different lighting conditions and match my device's system preference

## Acceptance Criteria
1. New "APPEARANCE" section added to Settings screen below "WORKFLOW" section
2. Appearance section shows theme selector with options: "Light", "Dark", "System" (follows system preference)
3. Theme preference stored in user preferences store and persisted to database
4. App applies theme colors immediately when theme changes
5. All screens and components respect theme (use theme-aware colors from design system)
6. Theme persists across app restarts
7. "System" option respects device system theme (light/dark mode)

**Theme Store Pattern:**
```typescript
// src/stores/themeStore.ts
interface ThemeStore {
  themePreference: 'light' | 'dark' | 'system';
  resolvedTheme: 'light' | 'dark';
  setThemePreference: (theme: 'light' | 'dark' | 'system') => Promise<void>;
  getColors: () => Colors; // Returns theme-aware colors
}
```

**ThemeProvider Component Pattern:**
```typescript
// src/components/ThemeProvider.tsx
import React, { useMemo } from 'react';
import { useThemeStore } from '../stores/themeStore';
import { getColors } from '../design-system/colors';

const ThemeContext = React.createContext<{ 
  theme: 'light' | 'dark', 
  colors: ReturnType<typeof getColors> 
} | null>(null);

export const ThemeProvider = ({ children }: { children: React.ReactNode }) => {
  const { resolvedTheme, getColors } = useThemeStore();
  const colors = useMemo(() => getColors(resolvedTheme), [resolvedTheme]);
  const value = useMemo(() => ({ theme: resolvedTheme, colors }), [resolvedTheme, colors]);
  
  return (
    <ThemeContext.Provider value={value}>
      {children}
    </ThemeContext.Provider>
  );
};

export const useTheme = () => {
  const context = React.useContext(ThemeContext);
  if (!context) {
    throw new Error('useTheme must be used within ThemeProvider');
  }
  return context;
};
```

**Alternative: Direct Hook Pattern (if not using Context):**
```typescript
// src/design-system/colors.ts
export const useTheme = () => {
  const { resolvedTheme, getColors } = useThemeStore();
  const colors = useMemo(() => getColors(resolvedTheme), [resolvedTheme]);
  return { theme: resolvedTheme, colors };
};
```

**Note:** Choose one approach - either ThemeProvider with Context (better for React patterns) or direct hook (simpler, Zustand handles reactivity)

### Technical Constraints

**Theme Resolution Logic:**
- If `theme_preference === 'system'`: Use device system theme (light/dark)
- If `theme_preference === 'light'`: Always use light theme
- If `theme_preference === 'dark'`: Always use dark theme
- Resolved theme (`'light' | 'dark'`) is computed from preference + system theme

**System Theme Detection:**
- Use `Appearance.getColorScheme()` from `react-native` (returns `'light' | 'dark' | null`)
- Or use `useColorScheme()` hook (returns `'light' | 'dark'`)
- Listen for changes: `Appearance.addChangeListener(({ colorScheme }) => { ... })`

**Performance:**
- Theme changes should be instant (no delay)
- Color lookups should be memoized to avoid re-renders
- System theme listener should be cleaned up on unmount

**Backward Compatibility:**
- Existing users without theme_preference get default 'system'
- Migration sets default to 'system' for all existing users
