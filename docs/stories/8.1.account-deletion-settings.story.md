# Story 8.1: Account Deletion in Settings

## Status
Done

## Epic Context
**Epic 8: Account Management (Post-MVP)**
This story is part of Epic 8, a post-MVP epic focused on user account management features. Epic 8 is not yet defined in the PRD but represents essential user control features for data privacy and GDPR compliance. This story enables users to permanently delete their accounts and all associated data.

## Story
**As a** user  
**I want to** delete my account from the Settings screen  
**So that** I can permanently remove my data and stop receiving emails if I no longer want to use the app

## Acceptance Criteria
1. Settings screen displays "Delete Account" option in Account section (below email display)
2. Tapping "Delete Account" shows confirmation alert with warning message
3. Confirmation alert includes:
   - Warning: "This action cannot be undone. All your tasks, preferences, and data will be permanently deleted."
   - Two buttons: "Cancel" and "Delete Account" (destructive/red)
4. If user confirms deletion:
   - Soft delete user record: `UPDATE users SET deleted_at = NOW() WHERE id = ?`
   - Delete Supabase Auth user: `supabase.auth.admin.deleteUser(auth_id)` (via Edge Function)
   - Sign out user from app immediately
   - Navigate to AuthScreen
5. If deletion fails, show error message and keep user signed in
6. After successful deletion, user cannot log back in with same email (auth user deleted)

### Data Models

**Users Table Schema:**
[Source: docs/architecture/database-schema-data-model.md, supabase/migrations/001_users_table.sql]

```sql
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  email VARCHAR(255) UNIQUE NOT NULL,
  auth_id UUID UNIQUE NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  deleted_at TIMESTAMP DEFAULT NULL,
  -- ... other fields
);
```

**Soft Delete Pattern:**
[Source: docs/architecture/database-schema-data-model.md]

- Users table has `deleted_at` field for soft deletion
- Soft delete preserves data for audit trail and recovery
- RLS policies should filter `deleted_at IS NULL` to exclude deleted users
- Hard delete of `auth.users` record triggers CASCADE on `users.auth_id` foreign key

**Cascading Deletes:**
[Source: supabase/migrations/001_users_table.sql, docs/architecture/database-schema-data-model.md]

- Tasks table: `user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE`
- Payments table: `user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE`
- Email logs table: `user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE`

When `auth.users` record is deleted:
- `users.auth_id` CASCADE deletes user record
- Related tasks, payments, email_logs are CASCADE deleted (hard delete)

**Note:** Soft delete on `users` table means related records remain in database but are inaccessible via RLS. Hard delete of auth user triggers CASCADE which permanently removes all related data.

**Implementation Pattern:**
[Source: docs/architecture.md - Edge Functions pattern, supabase/functions/]

**Note:** Verify authentication pattern against existing Edge Functions. Common patterns:
- Using `createClient` with service role key for admin operations
- Extracting JWT from Authorization header
- Using `supabase.auth.getUser()` or `supabase.auth.getUser(token)` depending on Supabase version

```typescript
// supabase/functions/delete-user-account/index.ts
import { createClient } from '@supabase/supabase-js'

const supabase = createClient(
  Deno.env.get('SUPABASE_URL')!,
  Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')! // Required for admin.deleteUser()
)

Deno.serve(async (req: Request) => {
  // Get authenticated user from Authorization header
  const authHeader = req.headers.get('Authorization')
  if (!authHeader) {
    return new Response(JSON.stringify({ success: false, error: 'Unauthorized' }), { status: 401 })
  }

  // Extract user from JWT token
  // NOTE: Verify exact pattern with existing Edge Functions or Supabase docs
  const token = authHeader.replace('Bearer ', '')
  const { data: { user }, error: authError } = await supabase.auth.getUser(token)
  
  if (authError || !user) {
    return new Response(JSON.stringify({ success: false, error: 'Invalid token' }), { status: 401 })
  }

  try {
    // Find user record
    const { data: userRecord, error: userError } = await supabase
      .from('users')
      .select('id, auth_id')
      .eq('auth_id', user.id)
      .single()

    if (userError || !userRecord) {
      return new Response(JSON.stringify({ success: false, error: 'User not found' }), { status: 404 })
    }

    // Soft delete user record
    const { error: softDeleteError } = await supabase
      .from('users')
      .update({ deleted_at: new Date().toISOString() })
      .eq('id', userRecord.id)

    if (softDeleteError) {
      return new Response(JSON.stringify({ success: false, error: 'Failed to delete user record' }), { status: 500 })
    }

    // Hard delete auth user (triggers CASCADE on related tables)
    const { error: authDeleteError } = await supabase.auth.admin.deleteUser(user.id)

    if (authDeleteError) {
      // Rollback soft delete if auth deletion fails
      await supabase
        .from('users')
        .update({ deleted_at: null })
        .eq('id', userRecord.id)
      
      return new Response(JSON.stringify({ success: false, error: 'Failed to delete auth user' }), { status: 500 })
    }

    return new Response(JSON.stringify({ success: true, message: 'Account deleted successfully' }), { status: 200 })
  } catch (error) {
    return new Response(JSON.stringify({ success: false, error: String(error) }), { status: 500 })
  }
})
```

**Client-Side Call:**
```typescript
// In Settings screen
const handleDeleteAccount = async () => {
  const { data: { session } } = await supabase.auth.getSession()
  if (!session) return

  const response = await fetch(`${SUPABASE_URL}/functions/v1/delete-user-account`, {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${session.access_token}`,
      'Content-Type': 'application/json'
    }
  })

  const result = await response.json()
  if (result.success) {
    // Sign out and navigate to auth screen
    await supabase.auth.signOut()
    // Navigation handled by auth state change
  } else {
    Alert.alert('Error', result.error || 'Failed to delete account')
  }
}
```

### Technical Constraints

**Security Considerations:**
[Source: docs/architecture/security-privacy.md]

- Account deletion must be authenticated (user can only delete their own account)
- Edge Function must verify user identity via JWT token
- Use service role key only in Edge Function (never expose to client)
- GDPR compliance: User has right to data deletion

**Deletion Strategy:**
- Soft delete on `users` table preserves audit trail
- Hard delete of `auth.users` triggers CASCADE on foreign keys
- Related records (tasks, payments, email_logs) are permanently deleted
- User cannot log back in after auth user deletion

**Error Handling:**
- If soft delete succeeds but auth delete fails: Rollback soft delete
- If Edge Function call fails: Show error, keep user signed in
- Network errors: Show user-friendly error message

**RLS Policy Updates:**
- Users SELECT policy should exclude soft-deleted users: `WHERE deleted_at IS NULL`
- Tasks/payments/email_logs policies already filter via user relationship (should exclude deleted users automatically)
