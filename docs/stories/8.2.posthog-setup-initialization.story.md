## Dev Notes

### Previous Story Insights
[Source: docs/stories/8.1.sentry-setup-crash-reporting.story.md]

**Key Patterns from Story 8.1 (Sentry Integration):**
1. **Initialization Module Pattern**: Created `src/lib/sentry.ts` with `initSentry()` function
   - Pattern: Separate module for service initialization
   - Error handling: Graceful degradation if DSN missing (log warning, don't crash)
   - Export service instance for use throughout app

2. **App.tsx Integration Pattern**: 
   - Import initialization function at top of file
   - Call initialization BEFORE React renders (outside component, at module level)
   - Sentry initialized: `initSentry()` called before `export default function App()`
   - PostHog should follow same pattern: `initPostHog()` called after `initSentry()`

3. **Environment Variables Pattern**:
   - Use `EXPO_PUBLIC_*` prefix for app-level variables
   - Access via `process.env.EXPO_PUBLIC_*` in app code
   - Configure in EAS secrets for production builds
   - Add to `.env.example` with placeholder values

4. **Error Handling Pattern**:
   - Check for missing config, log warning in dev mode
   - Don't crash app if service initialization fails
   - Use `__DEV__` flag for dev-only logging

5. **Package Installation**:
   - Sentry used `@sentry/react-native` v7.6.0
   - PostHog should use `posthog-react-native` (official React Native package)
