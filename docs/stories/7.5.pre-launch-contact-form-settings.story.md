# Story 7.5: Pre-Launch - Contact Form in Settings

## Status
Approved

## Story
**As a** user  
**I want to** contact the support team directly from the Settings screen  
**So that** I can report issues, ask questions, or provide feedback without leaving the app

## Acceptance Criteria
1. New "SUPPORT" section added to Settings screen below "WORKFLOW" section
2. "Contact Us" row displays in SUPPORT section with disclosure indicator
3. Tapping "Contact Us" opens modal with form fields: Name (optional), Email (pre-filled from session), Message (required)
4. Form submission inserts data to `contacts` table in Supabase
5. After successful insert, Edge Function `send-email` is triggered to send notification email to support
6. User sees success message: "Thanks! We'll get back to you soon."
7. Form validates: Message is required (show error if empty)

      ```sql
      DROP POLICY IF EXISTS "contacts_insert_own" ON contacts;
      CREATE POLICY "contacts_insert_own" 
        ON contacts 
        FOR INSERT 
        WITH CHECK (
          user_id IS NULL OR
          EXISTS (
            SELECT 1 FROM users 
            WHERE users.id = contacts.user_id 
            AND users.auth_id = auth.uid()
          )
        );
      ```

### Database Schema

**Contacts Table:**
```sql
CREATE TABLE contacts (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id UUID REFERENCES users(id) ON DELETE SET NULL,
  name VARCHAR(255) DEFAULT NULL,
  email VARCHAR(255) NOT NULL,
  message TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);
```

**RLS Policy:**
- INSERT policy: `contacts_insert_own` - Users can insert contacts with their own user_id or NULL (anonymous contacts)
- SELECT policy: Not needed - Service role (used by admin/Edge Functions) bypasses RLS
- Policy allows anonymous contacts (user_id = NULL) for users who want to contact support without account

### Technical Constraints

**Form Validation:**
- Message field: Required (cannot be empty or whitespace-only) - Show error Alert: "Message is required"
- Email field: Basic format validation using regex `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` - Show error Alert: "Please enter a valid email address"
- Name field: Optional (no validation needed)

**Error Handling:**
- Database insert errors: Show Alert with user-friendly message
- Edge Function errors: Log but don't fail (contact was saved to DB)
- Network errors: Show Alert with retry option

**Privacy:**
- User email pre-filled but editable (users may want to use different email)
- User ID stored if authenticated, NULL if anonymous contact
- RLS ensures users can only insert their own contacts
