# Magic Link Email Template Fix Guide

## Problem
Magic link emails are still showing Supabase branding even after configuration. This happens because Supabase uses **different email templates** depending on whether the user is new or existing:

- **"Confirm signup"** template → Used for NEW users (first-time signup)
- **"Magic Link"** template → Used for EXISTING users (returning sign-ins)

## Solution
You need to configure **BOTH templates** in Supabase Dashboard to ensure all emails show TodoTomorrow branding.

## Quick Fix Steps

### Step 1: Configure "Confirm signup" Template (For New Users)

1. Log in to [Supabase Dashboard](https://supabase.com/dashboard)
2. Select your project
3. Navigate to: **Authentication** → **Email Templates**
4. Click on **"Confirm signup"** template
5. Update the **Subject** field to: `"Confirm your TodoTomorrow account"` or `"Welcome to TodoTomorrow"`
6. Copy the HTML from `docs/stories/8.2-confirm-signup-template-design.html`
7. Paste it into the **Body (HTML)** field
8. **Important:** Ensure `{{ .ConfirmationURL }}` is preserved exactly as shown
9. Click **Save**

### Step 2: Configure "Magic Link" Template (For Existing Users)

1. Still in **Authentication** → **Email Templates**
2. Click on **"Magic Link"** template
3. Update the **Subject** field to: `"Your TodoTomorrow Magic Link"` or `"Sign in to TodoTomorrow"`
4. Copy the HTML from `docs/stories/8.2-magic-link-template-design.html`
5. Paste it into the **Body (HTML)** field
6. **Important:** Ensure `{{ .ConfirmationURL }}` is preserved exactly as shown
7. Click **Save**

### Step 3: Verify Configuration

1. Check that both templates show your custom HTML (not the default Supabase template)
2. Verify the subject lines are updated
3. Test with a NEW email address (will use "Confirm signup" template)
4. Test with an EXISTING email address (will use "Magic Link" template)

## Why This Happens

### Issue 1: Different Templates for New vs Existing Users
When you call `signInWithOtp()`:
- If the email **doesn't exist** in Supabase → Uses **"Confirm signup"** template
- If the email **already exists** → Uses **"Magic Link"** template

This is why you're seeing "Confirm your signup" emails - those are for new users!

### Issue 2: Supabase Footer Cannot Be Removed with Default SMTP
Even after customizing templates, Supabase **automatically appends** "powered by Supabase ⚡" footer when using their default SMTP. This is by design and cannot be disabled.

**The only way to remove it is to use custom SMTP.** See `8.2-CUSTOM-SMTP-SETUP-GUIDE.md`.

## Troubleshooting

**Still seeing Supabase branding?**
1. **Check if you configured BOTH templates** (see Step 1 & 2 above)
2. **Check if "powered by Supabase" footer appears:**
   - If YES → You need custom SMTP (see `8.2-CUSTOM-SMTP-SETUP-GUIDE.md`)
   - If NO → Template configuration issue (see below)
3. Make sure you clicked **Save** after updating each template
4. Try requesting a new magic link after saving
5. Clear your email cache or check a different email client
6. Verify the HTML was copied completely (check for `{{ .ConfirmationURL }}`)

**Email not working after update?**
- Ensure `{{ .ConfirmationURL }}` is exactly as shown (Go Templates syntax)
- Don't modify the template variable syntax
- Check for HTML syntax errors in the Supabase Dashboard

**Sender name still shows "Supabase Auth"?**
- Sender name requires custom SMTP configuration (not just template customization)
- This is expected behavior with Supabase's default SMTP
- To change sender name, you'll need to configure custom SMTP with your domain email
- See `8.2-CUSTOM-SMTP-SETUP-GUIDE.md` for instructions
