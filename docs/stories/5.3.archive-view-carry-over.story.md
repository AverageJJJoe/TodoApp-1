## Story
**As a** Carry Over mode user,  
**I want to** view completed tasks in Archive,  
**So that** I can review my accomplishments

## Acceptance Criteria
1. Tab bar appears: "Active | Archive" (only in Carry Over mode)
2. Archive tab queries: `SELECT * FROM tasks WHERE user_id = ? AND status = 'completed' ORDER BY completed_at DESC`
3. Tasks show: Task text (from `text` field) + completion timestamp
4. Empty state: "No completed tasks yet! 🎉"
5. Read-only (no editing in Archive)

### Database Schema Context
[Source: `docs/architecture/database-schema-data-model.md`, lines 58-85]

**Tasks Table - Completion Fields:**
- `status VARCHAR(20) NOT NULL DEFAULT 'open' CHECK (status IN ('open', 'completed', 'archived'))`
  - Status enum: `'open'` (default), `'completed'`, `'archived'`
  - Archive query filters by `status = 'completed'`
- `completed_at TIMESTAMP DEFAULT NULL`
  - Timestamp when task was completed
  - Used for ordering completed tasks: `ORDER BY completed_at DESC`
  - Used for stats calculation (tasks this week)
- `deleted_at TIMESTAMP DEFAULT NULL`
  - Soft delete timestamp (NULL if not deleted)
  - Archive query must exclude deleted tasks: `.is('deleted_at', null)`

**Query Pattern:**
```typescript
// Get user.id first (auth_id → user_id conversion)
const { data: user } = await supabase
  .from('users')
  .select('id')
  .eq('auth_id', session.user.id)
  .maybeSingle();

// Query completed tasks
const { data } = await supabase
  .from('tasks')
  .select('*')
  .eq('user_id', user.id)
  .eq('status', 'completed')
  .is('deleted_at', null)
  .order('completed_at', { ascending: false });
```

**Index for Performance:**
- `idx_tasks_completed_at` exists: `CREATE INDEX idx_tasks_completed_at ON tasks(user_id, completed_at DESC) WHERE status = 'completed'`
- Query should use this index automatically for optimal performance

**Stats Calculation Pattern:**
```typescript
const getArchiveStats = () => {
  const now = new Date();
  const startOfWeek = new Date(now.setDate(now.getDate() - now.getDay())); // Monday
  startOfWeek.setHours(0, 0, 0, 0);
  const endOfWeek = new Date(startOfWeek);
  endOfWeek.setDate(endOfWeek.getDate() + 6);
  endOfWeek.setHours(23, 59, 59, 999);
  
  const weekTasks = completedTasks.filter(task => {
    if (!task.completed_at) return false;
    const completed = new Date(task.completed_at);
    return completed >= startOfWeek && completed <= endOfWeek;
  });
  
  return weekTasks.length;
};
```

### Technical Constraints

**Workflow Mode Conditional:**
- Tab bar MUST only show when `workflowMode === 'carry_over'`
- Fresh Start mode: No archive functionality (tasks reset daily, no completion state)
- Carry Over mode: Archive tab available, shows completed tasks

**Query Performance:**
- Archive query should use existing index: `idx_tasks_completed_at`
- Query filters: `user_id`, `status = 'completed'`, `deleted_at IS NULL`
- Ordering: `completed_at DESC` (most recent first)

**Read-Only Mode:**
- Archive tasks must NOT be editable
- No swipe-to-delete in archive
- No edit modal in archive
- Checkbox not interactive (always shows completed state)

**Empty State:**
- Active tab: "Tap + to add your first task"
- Archive tab: "No completed tasks yet! 🎉"
- Must differentiate based on `activeTab` state

**Stats Footer:**
- Only show when archive has tasks (`completedTasks.length > 0`)
- Count tasks completed in current week (Monday-Sunday)
- Use `completed_at` timestamp for week calculation

### Security Considerations
[Source: `docs/architecture/database-schema-data-model.md` RLS policies]

- Tasks table has RLS policies ensuring users can only query their own tasks
