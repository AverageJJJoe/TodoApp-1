# Custom SMTP Setup Guide - Remove Supabase Footer

## Problem
Even after customizing email templates, Supabase automatically appends "powered by Supabase ⚡" footer when using their default SMTP. The only way to remove this is to use a **custom SMTP provider**.

Additionally, you're experiencing bounce back issues which could restrict email sending privileges.

## Solution: Use Resend for Auth Emails

✅ **Good news:** You already have Resend configured and working for daily task emails!  
✅ **Resend API key:** Already in Supabase secrets (`RESEND_API_KEY`)  
✅ **Resend sender email:** Already configured (`RESEND_FROM_EMAIL`)

We just need to configure Supabase Auth to use Resend as the custom SMTP provider for authentication emails (magic links, signup confirmations).

## Benefits
✅ **Remove Supabase footer** - Full control over email content  
✅ **Better deliverability** - Resend has better reputation than Supabase default SMTP  
✅ **Custom sender name** - Show "TodoTomorrow" instead of "Supabase Auth"  
✅ **Reduce bounce rates** - Better email infrastructure  
✅ **Consistent email provider** - Use Resend for both daily emails AND auth emails  

## Prerequisites
✅ Resend account (already have)  
✅ Resend API key in Supabase secrets (already configured - `RESEND_API_KEY`)  
✅ Resend sender email configured (already configured - `RESEND_FROM_EMAIL`)  
✅ Domain email verified in Resend (check Resend dashboard if needed)

## Step 1: Get Your Resend API Key

Since Supabase shows secrets as SHA256 digests (hardened), you'll need to get the actual API key value from one of these sources:

**Option 1: Get from Resend Dashboard (Recommended)**
1. Go to [Resend Dashboard](https://resend.com/api-keys)
2. Navigate to **API Keys** section
3. Find your active API key (or create a new one if needed)
4. Copy the API key value (it starts with `re_`)
5. **Note:** You can only see the full key when you first create it, so if you don't see it, you may need to create a new one

**Option 2: Check Your Local Environment/Code**
1. Check if you have the API key saved locally in:
   - `.env` file (if you have one locally)
   - Your code editor's environment variables
   - Password manager (if you saved it there)
   - Previous documentation or notes

**Option 3: Create a New Resend API Key**
1. Go to [Resend Dashboard](https://resend.com/api-keys)
2. Click **"Create API Key"**
3. Give it a name (e.g., "Supabase Auth SMTP")
4. Copy the key immediately (you won't be able to see it again!)
5. **IMPORTANT:** Update the `RESEND_API_KEY` secret in Supabase Edge Functions (see Step 1b below)

**After getting the API key:**
- The key starts with `re_` (e.g., `re_1234567890abcdef...`)
- This is what you'll paste into the SMTP Password field

## Step 1b: Update RESEND_API_KEY Secret in Supabase (If You Created a New Key)

**⚠️ IMPORTANT:** If you created a new Resend API key, you MUST update it in Supabase Edge Functions secrets so your daily task emails continue to work!

1. **Go to Supabase Edge Functions Secrets:**
   - Supabase Dashboard → **Edge Functions** → **Secrets**
   - Or direct: `https://supabase.com/dashboard/project/[YOUR_PROJECT]/functions/secrets`

2. **Update RESEND_API_KEY:**
   - Find `RESEND_API_KEY` in the list
   - Click the **trash icon** to delete the old one (or use "Add New Secrets" to add a new one)
   - In the "ADD NEW SECRETS" section:
     - **Key:** `RESEND_API_KEY`
     - **Value:** Paste your new Resend API key (the one you just created)
   - Click **"Save"**

3. **Verify:**
   - The new `RESEND_API_KEY` should appear in the list
   - Your daily task emails will continue working with the new key
   - Your SMTP configuration will use the same key

**Note:** Both your daily task emails (Edge Functions) and auth emails (SMTP) will now use the same Resend API key, which is perfect!

## Step 2: Configure Custom SMTP in Supabase Auth

**Before proceeding:** Make sure you've updated `RESEND_API_KEY` in Supabase Edge Functions secrets (Step 1b) if you created a new key!

1. **Navigate to SMTP Settings:**
   - Go to Supabase Dashboard → **Project Settings** → **Auth** → **SMTP Settings**
   - Or direct path: Project Settings → Auth → scroll to "SMTP Settings" section

2. **Enable Custom SMTP:**
   - Toggle **"Enable Custom SMTP"** to ON

3. **Enter SMTP Configuration:**
   
   **For Resend, use these settings:**
   
   - **SMTP Host:** `smtp.resend.com`
   - **SMTP Port:** `465` (SSL) or `587` (TLS) - try `587` first
   - **SMTP User:** `resend`
   - **SMTP Password:** Your Resend API key (from `RESEND_API_KEY` secret, starts with `re_`)
   - **Sender Email:** Use the same email from `RESEND_FROM_EMAIL` secret (likely `hello@todotomorrow.com`)
   - **Sender Name:** `TodoTomorrow` (this will show instead of "Supabase Auth")
   - **Enable Secure Email:** ✅ Yes (use SSL/TLS)

   **Quick reference:**
   ```
   Host: smtp.resend.com
   Port: 587 (TLS) or 465 (SSL)
   Username: resend
   Password: [Your RESEND_API_KEY value]
   Sender Email: [Your RESEND_FROM_EMAIL value]
   Sender Name: TodoTomorrow
   ```

4. **Test SMTP Connection:**
   - Click **"Send Test Email"** or **"Test Connection"** button (if available)
   - Enter your email address
   - Verify you receive the test email
   - **Important:** Check that the email does NOT have "powered by Supabase" footer
   - **Important:** Check that sender shows as "TodoTomorrow" instead of "Supabase Auth"

5. **Save Configuration:**
   - Click **"Save changes"** button (green button at bottom)
   - Wait for confirmation that settings are saved
   - **Note:** The sender email validation error may resolve after enabling custom SMTP and saving

## Troubleshooting: Sender Email Validation Error

If you see "Must be a valid email" error on the sender email field:

1. **Check email format:**
   - Ensure it's exactly `hello@todotomorrow.com` (no spaces, correct domain)
   - Try removing and re-typing it

2. **Verify email in Resend:**
   - Go to [Resend Dashboard](https://resend.com/domains)
   - Check if `todotomorrow.com` domain is verified
   - Or check if `hello@todotomorrow.com` email is verified
   - If not verified, you may need to verify it in Resend first

3. **Try enabling SMTP first:**
   - Sometimes the validation error clears after enabling the toggle
   - Enable "Custom SMTP" toggle first, then check if error persists

4. **Alternative sender email:**
   - If domain isn't verified, you can use Resend's default verified email
   - Check Resend Dashboard → Domains or Settings for your verified sender email
   - Common formats: `onboarding@resend.dev` or your verified domain email

## Troubleshooting

### SMTP Connection Fails
- **Check API key:** Ensure Resend API key is correct (starts with `re_`)
- **Check port:** Try port `587` (TLS) if `465` (SSL) doesn't work
- **Check sender email:** Must be verified in Resend dashboard
- **Check firewall:** Ensure Supabase can reach `smtp.resend.com`

### Emails Still Show Supabase Footer
- **Verify SMTP is enabled:** Check that "Enable Custom SMTP" is ON
- **Check sender email:** Must be verified in Resend
- **Clear cache:** Wait a few minutes and try again (Supabase may cache settings)
- **Test email:** Send a test email to verify footer is removed

### Emails Not Delivered
- **Check Resend dashboard:** Look for delivery errors
- **Check spam folder:** Resend emails may go to spam initially
- **Verify domain:** If using custom domain, ensure DNS records are correct
- **Check rate limits:** Resend free tier is 100 emails/day

### Bounce Back Issues Persist
- **Review email addresses:** Ensure all addresses are valid
- **Check Resend logs:** Look for bounce reasons
- **Verify domain reputation:** Check Resend dashboard for domain health
- **Contact Resend support:** If issues continue
