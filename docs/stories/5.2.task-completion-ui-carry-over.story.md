# Story 5.2: Task Completion UI (Carry Over Mode)

## Status
✅ **Done**

## Story
**As a** Carry Over mode user,  
**I want to** mark tasks as complete with a checkbox,  
**So that** I can track what I've finished

## Acceptance Criteria
1. If `workflow_mode = 'carry_over'`: Show checkbox next to each task
2. Tapping checkbox triggers animation: Strike-through → Fade → Slide out (600ms)
3. Update: `UPDATE tasks SET completed_at = NOW() WHERE id = ?`
4. Haptic feedback on completion
5. Task removed from Active list

### Database Schema Context
[Source: `docs/architecture/database-schema-data-model.md`, line 58-85]

**Tasks Table - Completion Fields:**
- `status VARCHAR(20) NOT NULL DEFAULT 'open' CHECK (status IN ('open', 'completed', 'archived'))`
  - Status enum: `'open'` (default), `'completed'`, `'archived'`
  - Must be set to `'completed'` when task is marked complete
- `completed_at TIMESTAMP DEFAULT NULL`
  - Timestamp when task was completed
  - Set to `NOW()` when `status` changes to `'completed'`
  - Used for ordering completed tasks in Archive view (Story 5.3)

**CRITICAL:** Current `handleCompleteTask` only sets `status: 'completed'`, missing `completed_at`. Must update both fields.

**Update Pattern:**
```typescript
await supabase
  .from('tasks')
  .update({
    status: 'completed',
    completed_at: new Date().toISOString(), // ISO timestamp format
    updated_at: new Date().toISOString()
  })
  .eq('id', taskId);
```

### API Specifications

const { data, error } = await supabase

### Technical Constraints

**Haptic Feedback:**
- Use `expo-haptics` package (may need installation)
- Import: `import * as Haptics from 'expo-haptics'`
- Trigger: `Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Light)`
- **NOTE:** Haptic feedback only works on physical devices (not in simulator/emulator)

**Workflow Mode Conditional:**
- Checkbox must ONLY show when `workflowMode === 'carry_over'`
- Fresh Start mode: No checkbox, tasks cannot be "completed" (they reset daily)
- Carry Over mode: Checkbox visible, tasks can be marked complete and move to Archive

**Animation Performance:**
- Use `useNativeDriver: true` for transform and opacity animations (better performance)
- Color animations (borderColor, backgroundColor) cannot use native driver
- Animation must complete before removing task from list (600ms delay)

**Database Update:**
- Must update both `status` and `completed_at` fields
- Use ISO timestamp format: `new Date().toISOString()`
- Handle errors gracefully: Don't remove task if database update fails
