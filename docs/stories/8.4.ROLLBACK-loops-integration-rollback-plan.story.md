# Story 8.4 ROLLBACK: Loops Integration Rollback Plan

## Status
**ROLLBACK COMPLETE** ✅ - Launch Unblocked (2025-11-12)  
**Loops Integration:** ❌ **PERMANENTLY DEFERRED / ABANDONED** - Will explore simpler alternatives post-launch

## Decision Rationale

**Date:** 2025-11-12  
**Decision:** Roll back Loops integration to unblock launch

### Why Roll Back?

1. **Launch Stage Priority** - App is at launch stage; infrastructure debugging blocks launch momentum
2. **Complexity vs. Value** - Welcome emails are "nice-to-have", not critical for launch
3. **Technical Debt** - Multiple unresolved issues:
   - Database trigger payload serialization problems
   - pg_net function signature issues
   - Edge Function deployment complexity
   - Multiple migrations with potential conflicts
4. **"Free Until Traction" Principle** - Apply same wisdom as monetization: launch core functionality first, add polish post-launch
5. **User Validation First** - Better to add welcome emails after validating product-market fit with real users

### What Remains Working

- ✅ User signup and authentication
- ✅ Task management (core functionality)
- ✅ Daily task emails (via Resend - existing system)
- ✅ Magic link authentication (Supabase Auth)

### What Will Be Removed

- ❌ Welcome emails (can add post-launch)
- ❌ Day 3 "no tasks" emails (can add post-launch)
- ❌ Day 5 inactivity emails (can add post-launch)

## Rollback Execution Plan

### Phase 1: Database Cleanup (SQL Commands)

**Execute in Supabase Dashboard → SQL Editor** (run in this exact order):

```sql
-- ============================================
-- ROLLBACK: Loops Integration (Story 8.4)
-- Execute Date: [DATE]
-- ============================================

-- Step 1: Drop the welcome email trigger and function
DROP TRIGGER IF EXISTS on_user_signup_trigger_loops ON users;
DROP FUNCTION IF EXISTS trigger_loops_welcome();

-- Step 2: Drop the cron job
SELECT cron.unschedule('send-loops-scheduled-emails-daily');

-- Step 3: Remove tracking columns from users table
ALTER TABLE users 
  DROP COLUMN IF EXISTS last_active_at,
  DROP COLUMN IF EXISTS last_day3_email_sent_at,
  DROP COLUMN IF EXISTS last_day5_email_sent_at;

-- Step 4: Drop the indexes (if they exist)
DROP INDEX IF EXISTS idx_users_last_active_at;
DROP INDEX IF EXISTS idx_users_day3_email_sent;
DROP INDEX IF EXISTS idx_users_day5_email_sent;

-- Step 5: Clean up email_logs table (remove Loops entries)
-- First, check what exists:
SELECT COUNT(*) as loops_email_count 
FROM email_logs 
WHERE provider = 'loops';

-- If there are Loops entries, delete them:
DELETE FROM email_logs WHERE provider = 'loops';

-- Step 6: Revert email_logs table changes (if needed)
-- Note: Migration 012 added columns that might be used by other systems
-- Check if provider/email_type columns are used elsewhere before dropping
-- For now, leave columns but remove Loops-specific constraints

-- Remove Loops-specific check constraints (if they exist)
ALTER TABLE email_logs 
  DROP CONSTRAINT IF EXISTS chk_provider,
  DROP CONSTRAINT IF EXISTS chk_email_type;

-- Verify cleanup
SELECT 
  'Trigger exists' as check_item,
  COUNT(*) as count
FROM pg_trigger 
WHERE tgname = 'on_user_signup_trigger_loops'
UNION ALL
SELECT 
  'Function exists',
  COUNT(*)
FROM pg_proc 
WHERE proname = 'trigger_loops_welcome'
UNION ALL
SELECT 
  'Cron job exists',
  COUNT(*)
FROM cron.job 
WHERE jobname = 'send-loops-scheduled-emails-daily'
UNION ALL
SELECT 
  'Loops emails in email_logs',
  COUNT(*)
FROM email_logs 
WHERE provider = 'loops';
```

**Expected Result:** All counts should be 0.
