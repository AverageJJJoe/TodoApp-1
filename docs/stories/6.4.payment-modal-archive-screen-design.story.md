## Status

## Story
**As a** developer,  
**I want to** apply polished Lovable design to payment modal and archive screen,  
**so that** monetization and archive features match the app's visual quality

## Acceptance Criteria
1. Trial Badge component created (matches Lovable spec):
   - Pill shape (fully rounded)
   - Light yellow background (#FFF9E6 or HSL equivalent from design system)
   - Warning icon (⚡) + text
   - Pulse animation when < 3 days remain
2. Payment/Trial Modal (Epic 4) matches Lovable paywall design:
   - Cohort-specific messaging styling
   - Primary CTA button ("Unlock Premium")
   - Secondary option styling ("Use Free Tier")
   - Proper spacing and typography
3. Archive Screen (Epic 5, Story 5.3) matches Lovable Archive design:
   - Tab bar styling (iOS segmented control style, 44px height)
   - Completed tasks: Green checkmark, strikethrough text (#C6C6C8), gray timestamp
   - Stats footer ("📊 X tasks this week")
   - No FAB on Archive tab
4. Tab switching animation: Smooth slide (200ms) for tab bar, crossfade for content
5. All components use design system tokens

### Data Models

**User Data (for Trial Badge and Payment Modal):**
- **Source:** `docs/architecture/database-schema-data-model.md`
- User fields relevant to this story:
  - `trial_expires_at`: Timestamp for trial expiration
  - `trial_tasks_count`: Number of tasks created during trial
  - `cohort`: User cohort assignment (for cohort-specific messaging)
  - `grandfather_status`: Boolean for free forever users
  - `is_paid`: Boolean for payment status
- Query days remaining: Calculate from `trial_expires_at` using SQL or JavaScript date math
- Query tasks remaining: `100 - trial_tasks_count` (if using task limit gate)

**Task Data (for Archive Screen):**
- **Source:** `docs/architecture/database-schema-data-model.md`
- Task fields:
  - `id`: UUID primary key
  - `user_id`: Foreign key to users
  - `text`: Task content
  - `status`: 'open' | 'completed' | 'archived'
  - `completed_at`: Timestamp when task was completed
  - `created_at`: Task creation timestamp
  - `deleted_at`: Soft delete timestamp (NULL if not deleted)
- Archive query: `SELECT * FROM tasks WHERE user_id = ? AND status = 'completed' AND deleted_at IS NULL ORDER BY completed_at DESC`
- Stats query: Count tasks completed in current week: `WHERE completed_at >= start_of_week AND completed_at <= end_of_week`

### Technical Constraints

**Animation Library:**
- **Source:** `docs/cursor-implementation-guide.md`
- Use React Native Reanimated (`react-native-reanimated`) for all animations
- Do NOT use Framer Motion (it's web-only)
- Animation timings must match design system: 200ms for tab switching, 2s for pulse, 500ms for modal spring

**Platform Considerations:**
- iOS: Tab bar should match iOS segmented control appearance (native feel)
- Android: May need Material Design adjustments if required
- Web/PWA: Hover states are optional (not critical for mobile-first design)

**Accessibility Considerations:**
- Touch target minimum size: 44px x 44px (iOS Human Interface Guidelines)
- All interactive elements (buttons, tabs, badges) should meet minimum touch target size
- Ensure sufficient contrast ratios for text readability
- Consider screen reader support for payment modal (announce modal title and CTAs)

**State Management:**
- Use Zustand store (already established in project) for:
  - User data (trial info, cohort)
  - Task data (for archive queries)
  - Modal state (if needed)

**Security Considerations:**
- **IMPORTANT:** This story implements the **design/UI layer only** for payment modal and trial badge
- Payment security, validation, and processing logic will be handled in **Epic 4** (Payment Integration stories)
- The `onUpgrade` callback is a placeholder - actual payment processing, receipt validation, and security measures will be implemented in Epic 4 stories (Stories 4.6, 4.7, 4.8)
- This story focuses solely on visual design and user experience, not payment security
