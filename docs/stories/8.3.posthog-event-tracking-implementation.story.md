# Story 8.3: PostHog Event Tracking Implementation

## Status
Ready for Review

## Epic Context
**Epic 8: Sentry Crash Logging, PostHog Analytics & Loops Email Sequences - Post-Launch Enhancement**
This story is part of Epic 8, a post-launch epic focused on integrating Sentry for crash logging, PostHog for product analytics, and Loops for automated email sequences. This story implements custom event tracking for key user actions to enable behavior analysis and retention measurement.

**Dependencies:** Story 8.2 (PostHog Setup) must be complete. PostHog must be initialized and user identification configured before tracking events.

## Story
**As a** product manager  
**I want** key user actions tracked as PostHog events  
**So that** I can analyze user behavior and measure retention

## Acceptance Criteria
1. Custom events implemented for:
   - `task_added` - When user creates a task
   - `task_completed` - When user completes a task
   - `task_deleted` - When user deletes a task
   - `email_sent` - When daily email is sent (tracked in Edge Function)
   - `user_signed_up` - When user completes signup
   - `user_logged_in` - When user logs in
   - `paywall_viewed` - When paywall is shown
   - `purchase_completed` - When user purchases premium
2. Events include relevant properties (task_id, user_id, timestamp, etc.)
3. Events tracked in both app (React Native) and Edge Functions (Deno):
   - React Native: Use `posthog-react-native` package (from Story 8.2)
   - Edge Functions: Use PostHog HTTP API (`https://us.i.posthog.com/capture/`) or `posthog-node` SDK if compatible with Deno runtime
   - Document chosen approach for Edge Functions
4. User identification set on signup/login (PostHog `identify()`) - **Already implemented in Story 8.2**
5. Test events verified in PostHog dashboard

### Previous Story Insights
[Source: docs/stories/8.2.posthog-setup-initialization.story.md]

**Key Patterns from Story 8.2 (PostHog Setup):**
1. **PostHog Instance**: PostHog is initialized in `src/lib/posthog.ts` and exported as `PostHog`
   - Use `PostHog.capture()` or `PostHog.captureEvent()` for event tracking
   - PostHog automatically includes `user_id` and `timestamp` if user is identified
   - Check if PostHog is initialized before tracking (graceful degradation)

2. **User Identification**: Already implemented in Story 8.2
   - `identifyUser()` function in `src/lib/posthog.ts`

   - User is identified with `auth_id` (UUID) and properties: `email`, `cohort`
   - AC 4 is already satisfied (user identification on signup/login)

3. **Error Handling Pattern**:
   - Check if PostHog is initialized before tracking
   - Log warnings in dev mode if PostHog not available
   - Don't crash app if event tracking fails
   - Use `__DEV__` flag for dev-only logging

4. **Event Properties**:
   - PostHog automatically includes `user_id` if user is identified
   - PostHog automatically includes `timestamp`
   - Add custom properties as second parameter: `PostHog.capture(eventName, { property1: value1 })`

### PostHog Event Tracking Details
[Source: docs/prd/epic-8-posthog-loops-integration.md]

**React Native Event Tracking:**
- Use `PostHog.capture(eventName, properties)` method
- PostHog automatically includes `user_id` if user is identified
- PostHog automatically includes `timestamp`
- Custom properties passed as second parameter

**Edge Function Event Tracking:**
- Use PostHog HTTP API: `https://us.i.posthog.com/capture/` (or EU endpoint)
- POST request with JSON body:
  ```json
  {
    "api_key": "POSTHOG_API_KEY",
    "event": "event_name",
    "distinct_id": "user_id",
    "properties": {
      "property1": "value1",
      "property2": "value2"
    }
  }
  ```
- Alternative: Check if `posthog-node` SDK is compatible with Deno runtime
- Document chosen approach in completion notes

**Event Properties:**
- Standard properties: `user_id` (auto-added), `timestamp` (auto-added)
- Task events: `task_id`, `workflow_mode` (for task_added)
- User events: `email`, `cohort`
- Paywall events: `cohort`, `days_remaining`, `tasks_remaining`
- Purchase events: `cohort`, `price_cents`, `platform`, `unlock_method`
- Email events: `user_id`, `email`, `task_count`, `workflow_mode`, `cohort`
